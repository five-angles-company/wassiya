# Mobile (Expo / React Native)

`apps/mobile` is Expo Router + Convex + Clerk auth. A few things differ hard from the web apps.

## When to use
- Any change under `apps/mobile`, native modules, dev builds, mobile auth/token/SecureStore, Metro resolution.

## When NOT to use
- Web/admin (Next.js) or landing (Astro) — different runtimes and patterns.

## Hard requirements
- **A development build is mandatory — Expo Go will NOT work.** The app uses native modules (gesture-handler, reanimated, `expo-secure-store`) and the `@clerk/expo` config plugin. Use `npx expo prebuild` + `npx expo run:android` (or `run:ios` on macOS). Plugin changes need `prebuild --clean`.
- **`app.json` plugins must include `expo-secure-store` and `@clerk/expo`.** The Clerk plugin registers the native modules; without it the dev build starts but auth fails.

## Auth & state
- `ClerkProvider` (in `app/_layout.tsx`) takes `publishableKey` + `tokenCache` from `@clerk/expo/token-cache`, and wraps `ConvexProviderWithClerk`. **That order** — Convex reads Clerk's context.
- **Never hand-roll token storage.** `tokenCache` keeps the session in the keychain via `expo-secure-store`; Clerk owns refresh, so there is no `fetchAccessToken` bridge and no auth Zustand store. Never AsyncStorage for tokens.
- `ClerkProvider` calls `WebBrowser.maybeCompleteAuthSession()` itself — don't add it.
- Sign-in lives in `src/components/sign-in-card.tsx`: a combined email-code flow (`signIn.emailCode` → falls back to `signUp.create` on `form_identifier_not_found`) plus `useSSO()` for Google.
- Only public `EXPO_PUBLIC_*` vars ship in the bundle. **Never** `CLERK_SECRET_KEY`.
- Client/UI state → Zustand (`src/stores/preferences.ts`, persisted to AsyncStorage). Server state stays in Convex.
- See `auth-wiring` for the backend and dashboard side.

## Clerk API drift
Clerk Core 3 renamed most of the custom-flow surface. Verify against `node_modules/@clerk/expo/dist/**/*.d.ts` before writing — the installed package wins over docs or memory:
- `useSignIn()`/`useSignUp()` return `{ signIn, errors, fetchStatus }`; methods resolve to `{ error }` with a flat `error.code`. No `prepareFirstFactor`/`attemptFirstFactor`.
- End code flows with `finalize({ navigate })`, **not** `setActive`. SSO is the exception: `startSSOFlow()` still returns `{ createdSessionId, setActive }`.
- `useOAuth()` is deprecated → `useSSO()`. `@clerk/expo/secure-store` is deprecated → `resource-cache`.
- Any screen that can create a sign-up must render `<View nativeID="clerk-captcha" />`.
- Native components (`@clerk/expo/native`) and native hooks (`useSignInWithGoogle`) are dev-build-only and don't exist on web.

## Metro / monorepo
- Expo auto-configures Metro for the pnpm workspace. `@workspace/backend` exposes its API only through its `exports` field, so `metro.config.js` sets `config.resolver.unstable_enablePackageExports = true` so `import { api } from "@workspace/backend/api"` resolves.
- Native dirs (`android/`, `ios/`, `.expo/`) are generated by `expo prebuild` and **gitignored** (CNG) — regenerate, don't commit. They live where the app is, so they don't survive a folder rename — re-run prebuild.

## Gotchas
- A social provider must be enabled in the Clerk dashboard before its button works — it fails at runtime, not build time.
- **Windows file locks:** a running `turbo dev`/Metro locks `apps/mobile` dirs — stop it before renaming/moving the app folder.

## Verify
- Dev build launches; the email code arrives and signs in; a Convex `currentUser` query shows a non-null identity; relaunch stays signed in (token cache).
- `pnpm --filter mobile typecheck` passes.
